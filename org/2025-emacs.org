*** =org-qiita-export-buffer-to-book= の作成

後は =.org= ファイルからの Markdown ファイルの展開を実装します。幸い org ドキュメントの /subtree/ に対する /export/ という概念があり、 org-mode はこのような処理が得意です。

#+ATTR_TYPST: :breakable true
#+BEGIN_SRC elisp
(leaf ox-qmd
  :commands (org-qiita-export-buffer-to-book)
  :config
  ;; Converts org-mode tags into front matter tag.
  (defun qmd2-template-tags ()
    (let ((tags (or (mapcar #'substring-no-properties (org-get-tags))
                    "")))
      (string-join
       (mapcar (lambda (s) (format "\"%s\"" s)) tags)
       ",")))

  ;; Markdown file template for `@qiita/qiita-cli'.
  (defun qmd2-template (contents info)
    (let* ((title (or (substring-no-properties (car (plist-get info :title))) ""))
           (tags (qmd2-template-tags)))
      (concat
       "---\n"
       "title: \"" title "\"\n"
       "tags: [" tags "]\n"
       "private: false\n"
       "updated_at: \"\"\n"
       "id: null\n"
       "organization_url_name: null\n"
       "slide: false\n"
       "---\n\n"
       contents)))

  ;; The Qiita Markdown export backend, built on top of `ox-qmd'.
  (org-export-define-derived-backend 'qmd2 'qmd
    :options-alist
    '((:title "TITLE" nil nil t)
      (:tags "TAGS" nil nil space))
    :translate-alist '((template . qmd2-template)))

  ;; Exports a subtree of org file into a Markdown file.
  (defun org-qmd2-export-to-markdown (&optional async subtreep visible-only)
    (interactive)
    (let ((outfile (org-export-output-file-name ".md" subtreep)))
      (org-export-to-file 'qmd2 outfile async subtreep visible-only)))

  ;; Exports each level 1 heading into a Markdown file.
  (defun org-qiita-export-buffer-to-book (&optional org-dir)
    "Runs subtree export to each level 1 heading, respecting `#+BOOK_DIR'."
    (interactive)
    (require 'ox-qmd)
    (let* ((default-dir default-directory)
           (pub-dir (car (cdr (car (org-collect-keywords '("BOOK_DIR")))))))
      (cd pub-dir)
      (unwind-protect
          (org-map-entries
           (lambda ()
             (let ((exports (org-entry-get nil "EXPORT_FILE_NAME")))
               (when exports
                 (org-qmd2-export-to-markdown nil t))))
           "LEVEL=1")
        (cd default-dir)))))
#+END_SRC

#+BEGIN_SRC emacs-lisp
    (progn ;; Show full path in `find-file' after `embark-become'
      (defun my-embark-become-prepend-default-dir (orig-fun command input)
        "Prepend default-directory to INPUT when COMMAND is file-related."
        (if (and (memq command '(find-file find-file-other-window
                                           find-file-other-frame find-file-literally))
                 (not (string-prefix-p (expand-file-name default-directory)
                                       (expand-file-name input))))
            (let ((dir-with-slash (file-name-as-directory default-directory)))
              (if (equal input "")
                  (funcall orig-fun command dir-with-slash)
                (funcall orig-fun command (expand-file-name input dir-with-slash))))
          (funcall orig-fun command input)))

      (advice-add 'embark--become-command :around
                  #'my-embark-become-prepend-default-dir)))
#+END_SRC

** Bookmark を使用する

*** Mark とは

Mark はカーソル位置 (_point_) を表すデータです。 [[https://www.gnu.org/software/emacs/manual/html_node/emacs/Mark-Ring.html][Mark ring]] が普段からカーソル位置の変化を記録しており、 =consult-mark= で確認できます。 Mark は一時的なデータであり、 Emacs の終了時に失われます。

と書いてみたのですが、 100% 間違いを含む説明で申し訳ありません。

*** Bookmark とは

[[https://www.gnu.org/software/emacs/manual/html_node/emacs/Bookmarks.html][Bookmarks]] はファイル保存される mark のことだと思います。 Builtin の bookmark はフラットな一覧であるため、これらにタグを付けてフィルタリングして行きたいです。

*** Bookmark, Bookmark+

[[https://www.emacswiki.org/emacs/BookmarkPlus][Bookmark+]] は Emacs Wiki で開発・公開されているパッケージです。最新版にこだわりがなければ、 [[https://github.com/emacsmirror/bookmark-plus][GitHub のミラー]] から引っ張ってくるのが簡単そうです:

#+BEGIN_SRC elisp
(leaf bookmark+
  :ensure nil
  :vc (:url "https://github.com/emacsmirror/bookmark-plus"))
#+END_SRC

#+BEGIN_EXPORT md
:::note warn
設定不足で恐縮です。

Bookmark ファイルの更新は、 Emacs の終了時などまで遅延されます。 Bookmark の一時的な状態がメモリ上のみに存在するため、 Emacs が異常終了した場合にデータが失われる他、複数の Emacs 間の同期が取れません。

また Bookmark の変更の度にファイル保存する設定もありますが、 `bookmark+` の関数 (`bmkp-*`) のパフォーマンスが極端に落ちたため未設定です。
:::
#+END_EXPORT

*** 実装

**** Bookmark 保存

Bookmark を以下の形で保存したいです:

- 名称: =dir/file.ext:line= (自動設定)
- タグ: =repository/topic= (トピック部分はユーザ指定)

これらの計算用の関数です:

#+BEGIN_SRC elisp
(defun my/get-default-bookmark-name ()
  "dir/file.ext:line"
  (let* ((root (vc-git-root default-directory))
         (line (line-number-at-pos)))
    (format "%s:%d" (file-relative-name (buffer-file-name) root) line)))

(defun my/project-like-name ()
  "git root name or a fallback"
  (file-name-nondirectory
   (directory-file-name
    (or (vc-git-root default-directory)
        (directory-file-name default-directory)
        (buffer-name)))))
#+END_SRC

これを元に、カーソル位置をタグ付きで bookmark として保存するコマンドを作成しました:

#+BEGIN_SRC elisp
(defun my/bookmark-set ()
  "Create a bookmark at point with automatic file-based naming and auto tag."
  (interactive)
  (let ((bookmark-name (my/get-default-bookmark-name))
        (tag-name (consult-bookmark-tags-with-default "Tag: " t)))
    (let ((inhibit-message t))
      (bookmark-set bookmark-name nil t)
      (bmkp-add-tags bookmark-name `(,tag-name)))
    (message "Bookmark created: %s (tag: %s)" bookmark-name tag-name)))
#+END_SRC

#+BEGIN_SRC elisp
(defun consult-bookmark-tags (&optional prompt default-tag allow-new-p)
  (interactive)
  (require 'bookmark+)
  (let ((tags (bmkp-tags-list nil t)))
    (completing-read
     (or prompt "Tags: ")
     tags
     nil  ; No predicate
     (not allow-new-p)  ; Require match if new tags not allowed
     default-tag ; initial input
     nil  ; No hist
     default-tag ; default (fallback) value
     )))

(defun consult-bookmark-tags-with-default (&optional prompt allow-new-p)
  "`consult-bookmark-tags' with `<project>/' as the default tag name."
  (consult-bookmark-tags prompt (concat (my/project-like-name) "/") allow-new-p))
#+END_SRC

(defun my/consult--bookmark-candidates ()
  "Return bookmark candidates."
  (require 'bookmark+)
  (cl-loop for bm in bookmark-alist collect
           (let* ((name (car bm))
                  (tags (bmkp-get-tags bm))
                  (line-content (let ((filename (bookmark-get-filename bm))
                                      (pos (bookmark-get-position bm)))
                                  (cond
                                   ((and filename pos (file-exists-p filename) (not (file-directory-p filename)))
                                    (with-temp-buffer
                                      (insert-file-contents filename)
                                      (goto-char pos)
                                      (string-trim (thing-at-point 'line t))))
                                   ((and filename (file-directory-p filename))
                                    (format "[Directory: %s]" (file-name-nondirectory filename)))
                                   (filename
                                    (format "[File: %s]" (file-name-nondirectory filename)))
                                   (t "[Buffer]"))))
                  (tags-str (if tags
                                (propertize (mapconcat #'identity tags ", ") 'face 'consult-key)
                              ""))
                  ;; We're embedding nerd icon here..
                  (display-name (format "%-30s %-20s %s" (concat (nerd-icons-icon-for-file name) " " name) tags-str

                         'consult--candidate name))))

** Magit ユーザとして

*** 日常の Git 操作

Magit に慣れるためには、日常的な Git 操作を =magit= にするのが良いと思います。公式ドキュメントはリファレンスであってチュートリアルではないため、手探りで使っていく他に無さそうです。

=magit= 経由で Git を操作すると、本来あるべき Git の UI が明らかになります。たとえば =git push= は並列的に実行されるため、 push 完了まで待機する必要がありません。あるいは =cherry-pick= したければ、まず対象のブランチのログを表示し、 pick すべきコミットを選んでから =magit-cherry-pick= します。 Rebase 用のバッファから該当のコミットの内容を確認することができますし、 fixup コミットを平然と放つこともできます。

一度理解すれば、高度な機能を手足のように扱うことができます。 Magit を使うだけで、半ば Git の達人となることができるのだ……！

#+BEGIN_QUOTE
=bisect= などは改善の余地があるかもしれません。
#+END_QUOTE

*** 巨大リポジトリに対して

僕が Magit を最高だと思っているのは、所詮 Magit が軽快に動作する中小規模のリポジトリしか触っていないから、という面もあります。 [[https://github.com/NixOS/nixpkgs][=nixpkgs=]] 上で Magit を使うと、動作毎に 10 秒単位で遅延が発生するのは避けられません。 Linux Kernel のリポジトリでは遅過ぎる、という [[https://github.com/magit/magit/issues/2982][Issue]] もあります。ここは認めざるを得ないところではないかと。

*** =smerge-mode=

Conflict の解決のショートカットは Magit には無く、 =smerge-mode= を使います。

あまり conflict の解決作業が無い場合、 =smerge-mode= のショートカットを忘れがちです。探せば誰かの [[https://github.com/abo-abo/hydra][hydra]] があるので、こういうのを採用しても良いと思います:

https://github.com/kaushalmodi/.emacs.d/blob/2612774caabe9e84b6a2d45f017f97e7f07afcd0/setup-files/setup-diff.el#L181-L212
#+END_EXPORT

*** 3-way diff

=ediff= が Magit の一番難しい所だと思います。僕は =ediff= を使っていません。 Side-by-side の diff も 3-way diff も苦手なためです。所詮大した活動をしていないためかもしれませんね 🥺

*** =magit-blame=

Magit blame は blame のインライン表示といった機能です。僕にはこれが見づらくて、実のところ GitHub の blame を見ています。ブラウザからならば PR の内容にも飛べるので、リーダーとしての機能がテキストエディタに勝る面もあると思います。

VSCode のようにカーソル下に変更履歴を出したい場合は、 [[https://github.com/Artawower/blamer.el][=blamer.el=]] を使うことができます。

*** Hunk の内容

=magit-status= 中の diff に行番号が表示されないのは宿命だと思います。こうしてみると、それなりの妥協点がありますね。

*** おまけ

おまけとしてカーソル位置の行を GitHub で開く関数を……と思いきや、 [[https://github.com/rmuslimov/browse-at-remote][=browse-at-remote=]] を使うのが良さそうです:

この記事は [[https://qiita.com/advent-calendar/2025/emacs-25][Emacs 精進 Advent Calendar 2025]] 11 日目の投稿です。

** 背景

僕は [[https://github.com/emacs-evil/evil][Evil]] (Vim バインド) ユーザです。僕は Emacs ユーザであることを公言してますが、 evil ユーザであることは言及していないため、ガチガチの Emacsen だと認識されているかもしれません。この伏せ札を見せる日は来るのでしょうか。

さて evil について、簡単に設定を振り返ってみます。完全な設定を作れずに運用でごまかしている面が強いです。

** Evil の設定していない部分

設定していない部分、できていない部分から書いてみます。

*** Vim との互換性

Evil で使えない機能として、 =cgn= などのキーバインドが有ります。僕がエセ Vim 使いであるために、このようなニッチな Vim の機能は存在にすら気づいていないので、特に設定していません。無念……。

*** Emacs 内ターミナルとの相性

Evil と Emacs 内ターミナルの相性は悪いです。普通に =tmux= を使うのが楽だと思います。僕は Emacs 自体もターミナルから起動しています。

*** ターミナル内の制限

**** キー入力

Emacs をターミナル上で使用した場合、修飾キー + 記号キーなどの入力を正しく受け取ることができません。たとえば =Ctrl + ,= も認識できません。

Vim バインドを使うと、装飾キーを使うことが少なく、ほぼこの問題を回避できます。しばしば =Ctrl + RET= 等が欲しくなりますが、新しいキーバインドを作ったり、 =org-mode= ファイルのみ GUI から編集するなどの方法で凌いでいます。

**** Fringe, 画像表示

GUI の Emacs では、細い線を描けてとても格好良いです。ターミナルだと、いつものブロックで構成された画面が退屈です。

GUI の Emacs では自然に画像を表示できて、 =org-mode= でブログなどを書くと体験が良いです。ターミナルで =org-mode= を書くと、ブラウザとのプレビューを反復することになり、本来あるべきフロー (主観) から外れてしまいます。

**** ポップアップ

現在の Emacs では、ターミナルでポップアップウィンドウの機能 (_child frame_) を使用できません。これは次のメジャーリリースで解決するという噂があるので、非常に楽しみです。

もっとも、補完等は謎機能でポップアップ表示するため、特に困ることはありません。 Emacs の主な選択画面 (minibuffer) がポップアップ表示 *ではない* のも面白いですね。

** Evil の設定

少しだけ設定した部分を書いてみます。

*** Vim に近い挙動に修正

Evil Emacs が Vim では無さ過ぎてやられてしまう人は多いです。僕のようなエセ Vimmer であっても、以下の点は気になって (不完全ながら) 修正してみました。

**** 最下行カーソル

デフォルトの Emacs は、通常のエディタよりも 1 行下までカーソルが移動します。この挙動を抑制するために、僕は強引な advice を書いています:

#+BEGIN_SRC elisp
(defun my/disable-cursor-at-eof ()
  (unless (or (window-minibuffer-p) (<= (line-number-at-pos) 1))
    (when (= (point) (point-max))
      (forward-line -1))))
(add-hook 'post-command-hook #'my/disable-cursor-at-eof)
#+END_SRC

Emacs 内ターミナル等でめちゃめちゃ干渉したらすみません。

**** 起動時の画面分割

複数のファイルを引数に Vim を起動すると、 1 つのウィンドウに最初のファイルが開きます。

#+BEGIN_SRC sh
$ vim a b c # a が開く
#+END_SRC

複数のファイルを引数に Emac を起動すると、最後のファイルと =*Buffer List*= が開きます:

#+BEGIN_SRC sh
$ emacs -Q a b c # c と *Buffer List* が開く
#+END_SRC

僕の場合は、起動時に =delete-other-windows= を呼ぶことで、 =c= 以外のウィンドウが閉じるようにしています:

#+BEGIN_SRC elisp
(add-hook 'window-setup-hook #'delete-other-windows)
#+END_SRC

ズバり Vim の動作ではないですが、意外に修正が難しかったので、これだけにしています……。

**** =quit= 関連の挙動

ウィンドウを閉じた際に、 Emacs を終了して欲しかったり、逆に終了してほしく無い場合もあります。この辺りは地道に修正し、動作を合わせます:

#+BEGIN_SRC elisp
(defun my/evil-quit ()
  (interactive)
  (cond ((one-window-p) (my/evil-quit-all))
        (t (evil-quit))))

(defun my/evil-save-and-quit()
  (interactive)
  (save-buffer)
  (my/evil-quit))

(defun my/evil-quit-all ()
  (interactive)
  (cond ((= 1 (length (funcall tab-bar-tabs-function))) (evil-quit-all))
        (t (tab-bar-close-tab))))

;; NOTE: this is not perfect, e.g., when we press `C-w q`
(evil-ex-define-cmd "q[uit]" 'my/evil-quit)
(evil-ex-define-cmd "wq" 'my/evil-save-and-quit)
(evil-ex-define-cmd "qa[ll]" 'my/evil-quit-all)
#+END_SRC

もっとストレートな修正方法もあると思いますが、誤魔化しつつやってます。

*** コマンドの作成

=:ed<RET>= で =init.org= を開けるようにしています。この手の設定は簡単で良いですね:

#+BEGIN_SRC elisp
(evil-ex-define-cmd
 "ed" (lambda nil
        (interactive)
        (evil-edit
         (concat user-emacs-directory "init.org"))))
#+END_SRC

*** 日本語編集用

誰かが Vim で =C-j= を =、= に、 =C-l= を =。= にする設定記事を書いていました。同じようなことができます:

#+BEGIN_SRC elisp
(keymap-set evil-read-key-map "C-j" "、")
(keymap-set evil-read-key-map "C-l" "。")
#+END_SRC

この設定のおかげで、たとえば =f C-j= が =f、= になったりします。 =;= リピートもできます。日本語編集に必須です！

Evil やターミナル上の Emacs についての経験をつらつらと書いてみました。不完全な設定ばかりなので、デカデカと記事に書いたことは無かったと思いますが、この手の設定が効いて Vim から Evil Emacs に移行できたのを覚えています。酷い設定だったらすみません。。

*** =sql-sqlite= (SQL シェルの起動)

Emacs から =sql-sqlite= で =test.db= を開きます (空ファイルで良いです) 。 =hello= テーブルを作ってみます:

#+BEGIN_SRC sh

SQLite version 3.50.4 2025-07-30 19:33:53
Enter ".help" for usage hints.
sqlite> create table hello (msg TEXT);
sqlite> insert into hello values ('hello');
#+END_SRC

普通の SQL シェルですね。テーブル定義を確認してみます:

#+BEGIN_SRC sql
sqlite> .table
hello
sqlite> .schema hello
CREATE TABLE hello (msg TEXT);
sqlite> select * from hello;
hello
#+END_SRC

*** =org-mode= ファイルからの SQL 実行

せっかく Emacs を使っているならば、 one-shot なコマンドは =org-mode= から打っても良いかもしれません。 =(require 'ob-sqlite)= 後、以下のように実行 (=org-babel-execute-src-block=) できます:

#+BEGIN_EXPORT md
https://orgmode.org/worg/org-contrib/babel/languages/ob-doc-sqlite.html
#+END_EXPORT

#+BEGIN_SRC org
,#+BEGIN_SRC sqlite :db ./test.db
.table
,#+END_SRC

,#+RESULTS:
: hello
#+END_SRC

#+BEGIN_SRC org
,#+BEGIN_SRC sqlite :db ./test.db
.schema hello
,#+END_SRC

,#+RESULTS:
: CREATE TABLE hello (msg TEXT);
#+END_SRC

もしもすべてのコードブロックに =:db= を書くのが大変ならば、ファイル冒頭で =header-args= を指定すれば良いです:

#+PROPERTY: header-args :db ./test.db

,#+BEGIN_SRC sqlite
.table
,#+END_SRC

,#+RESULTS:
: hello
#+END_SRC

#+BEGIN_SRC sh
$ # review requested な PR を列挙する
$ gh pr list --search "review-requested:@me"

$ # review requested な PR 番号を列挙する
$ gh pr list --search "review-requested:@me" --json number

$ # review requested な PR の数を数える
$ gh pr list --search "review-requested:@me" --json number --jq length
#+END_SRC
